# Пакеты стандартов

## Purpose

Распространять переиспользуемые инженерные стандарты как обычные npm-пакеты документов, которые люди и AI читают без интерпретатора каталогов.

## ADDED Requirements

### Requirement: Five independently installable packages
Продукт SHALL предоставлять core, frontend, TypeScript, Svelte и Svelte SPA как пять отдельных npm-пакетов с независимыми версиями. Потребитель MUST иметь возможность установить выбранный набор без CLI и config-продуктов.

#### Scenario: Install a chosen subset
- **WHEN** потребитель устанавливает артефакты core и TypeScript
- **THEN** оба пакета доступны как документы без CLI, ESLint/Prettier-конфигов и автоматической установки остальных пакетов стандартов

### Requirement: README is the package entry point
Каждый пакет SHALL содержать README с применимостью и ссылками на все распространяемые в нём стандарты. README SHALL описывать соответствующие сочетания и известные ограничения совместимости текстом, без обязательного машинного каталога.

#### Scenario: Read an installed package
- **WHEN** читатель открывает README установленного пакета
- **THEN** он может определить область применения, прочитать рекомендации по совместимости и перейти по локальным ссылкам к стандартам без checkout исходного репозитория

### Requirement: Self-contained published documentation
Артефакт пакета SHALL включать README, связанные документы стандартов, лицензию и changelog. Локальные ссылки MUST вести внутрь артефакта. Планы/ревью разработчиков, приватные продуктовые материалы и внутренние tooling-файлы MUST NOT распространяться как стандарты.

#### Scenario: Verify isolated artifacts
- **WHEN** пять tarballs установлены во внешний consumer fixture
- **THEN** документы читаются, а локальные ссылки разрешаются без workspace links или загрузчика каталогов

#### Scenario: Missing document or forbidden file
- **WHEN** упакованный README ссылается на отсутствующий документ или tarball включает служебный review-файл
- **THEN** проверка артефакта завершается ошибкой с указанием пакета и проблемного пути

### Requirement: Document-only public interface
Использование пакета SHALL требовать только обычных npm-метаданных и читаемых документов. Оно MUST NOT требовать manifests, JSON-схем каталогов, разрешения профилей, выбора отдельных правил, генерации инструкций или проверки семантических зависимостей.

#### Scenario: Consume without catalog metadata
- **WHEN** потребитель устанавливает пакет с package.json и документацией, но без manifest.json
- **THEN** описанный сценарий чтения и применения пакета целиком остаётся доступным

### Requirement: Drafts remain distinct from approved standards
Черновики и тестовое содержание SHALL иметь явные пометки. Проверка инфраструктуры MUST NOT принимать реальные стандарты или разрешать публикацию; принятие содержания владельцем и явное одобрение публикации остаются отдельными условиями.

#### Scenario: Infrastructure passes with test documents
- **WHEN** тесты пакетов и потребителя проходят на тестовых документах
- **THEN** это доказывает только готовность инфраструктуры, а реальные черновики не становятся принятыми или опубликованными
