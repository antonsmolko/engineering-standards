# Proposal

Задача планирования: [#30](https://github.com/antonsmolko/engineering-standards/issues/30).
Владелец одобрил design в обсуждении (private input, not a public basis); публичная основа scope — [#30](https://github.com/antonsmolko/engineering-standards/issues/30). Реализация и разрешения merge/публикации остаются отдельными.

## Why

Потребителю нужны устанавливаемые инженерные документы для людей и AI. Текущий дизайн каталогов и CLI добавляет систему выбора правил и управления сгенерированными файлами, которая не нужна для согласованного начального сценария.

## What Changes

- Сохраняем пять независимо версионируемых пакетов документов: core, frontend, TypeScript, Svelte и Svelte SPA, их текущие имена и границы каталогов.
- Каждый выбранный пакет применяется целиком. README описывает применимость, ссылается на стандарты и поясняет сочетания пакетов текстом.
- Установка — через npm; ссылки на установленные README вручную добавляются в AGENTS.md потребителя. Конкретный AI-инструмент не требуется.
- **BREAKING**: убираем предложенный интерфейс manifest/schema/profile из активного продукта. Метаданные остаются в обычном package.json; совместимость описывается, а не вычисляется автоматически.
- Убираем CLI/config-пакеты из активных workspaces; отложенные идеи сохраняются в истории и документации, а не в публикуемых заглушках. Проверки и внешние tarball-тесты адаптируем к пяти пакетам документов.
- Используем существующий репозиторий и черновики стандартов. Инфраструктуру проверяем на тестовых документах до принятия реального содержания.
- Changesets, проверочный CI и явно одобренная публикация остаются последовательными, отдельно планируемыми изменениями. Этот change задаёт упрощённый контракт распространения документов, а не весь процесс выпуска.
- Планы и обсуждения ведём на русском; публикуемые стандарты и README — на английском. Две языковые версии возможны позднее и не входят в текущий scope.

## Capabilities

### New Capabilities

- `standards-packages`: пять независимо устанавливаемых пакетов документов с README как точкой входа и текстовым описанием применимости/совместимости.
- `manual-consumer-adoption`: применение пакетов целиком людьми и AI через npm и вручную поддерживаемые инструкции потребителя.

### Modified Capabilities

Нет. В OpenSpec пока нет основных specs. Новые specs описывают замену прежнего дизайна, а не утверждают, что существующая реализация уже им соответствует.

## Impact

Будущая реализация затронет корневые workspaces/lockfile/check, manifests/exports/README пяти пакетов стандартов, тесты каталогов и CLI, активные архитектурные документы и roadmap. Старые JSON exports удаляются до публикации; миграция опубликованных пакетов не заявляется. Черновики остаются черновиками до принятия владельцем.

Сейчас меняются только артефакты этого OpenSpec change. Задачи GitHub, пакеты и репозитории потребителей не меняются; merge, повышение версий и публикация не выполняются. Реализация идёт в ветках конкретных задач и отдельных проверяемых PR; прежние критерии задач необходимо согласовать с новым scope до выполнения. Принятие содержания и явные разрешения merge/публикации остаются отдельными условиями.
